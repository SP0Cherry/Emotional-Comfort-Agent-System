# 情感识别模块组会技术问答稿

## 一、回答原则

1. 先区分“工程集成”和“算法创新”，不把使用开源模型说成从零自研。
2. 明确区分三组数字：
   - Qwen 与最终模型在同一批 1000 条测试上的对比；
   - 最终模型在 1449 条 BRIGHTER 密封测试上的结果；
   - 另一套数据同源 train/test 的结果。
3. 不声称完成说话人隔离评测。
4. 不声称支持方言情绪识别，方言接口当前只返回普通话 fallback。
5. 不只报告成功结果，主动说明多标签融合和层级模型没有超过扁平模型。

---

## 二、模块与接口

### Q1：你负责的到底是什么？

**回答：**

> 我负责情感识别模块。输入是用户当前文本、语音和最近几轮上下文，输出是六类情绪分布、效价、唤醒度、强度、置信度、情绪趋势和风险信号。人格建模、回复生成和方言 TTS 由其他模块负责。

### Q2：为什么不用一个大模型直接完成所有事情？

**回答：**

> 情感识别需要稳定、结构化、可测试的输出。单独让 Qwen 按提示做情绪分类，在同一批 1000 条测试上只有 45.3% Accuracy、44.3% Macro-F1。需要注意的是，我们的提示里包含少量类别示例，因此严格说是少样本提示，不是零样本。我最终采用任务微调模型，并保留规则和 Qwen 作为保护及回退。

### Q3：微调模型和 Qwen 怎么配合？

**回答：**

> 默认由微调 RoBERTa 主导普通情绪分类。规则负责三类事情：保留明确的“平静”判断、防止模型把明确“睡不着/担心”误判成中性、独立进行风险提示。Qwen 只在微调模型不可用时作为回退。

### Q4：语音部分怎么融合？

**回答：**

> SenseVoice 负责普通话转写和粗粒度情绪标签；emotion2vec 提供更完整的语音情绪概率。浏览器还会提取音量、音高、有效语音比例和停顿，作为质量与唤醒度信号。语音不会简单覆盖文本，固定融合权重也经过测试。

### Q5：为什么规则不直接删掉？

**回答：**

> 规则并非主分类器，而是可靠性和安全兜底。它能保留明确平静、找到否定和反讽线索、提供可解释证据、在模型服务失败时维持系统运行。模型负责更广的语义覆盖。

### Q6：输出有哪些字段？

**回答：**

> 主要包括 `dominant_emotion`、`emotion_distribution`、`valence`、`arousal`、`intensity`、`confidence`、`temporal`、`quality`、`risk`、`evidence`、模型版本、延迟和降级原因。

### Q7：什么是 `decision_mode`？

**回答：**

> 我将输出分为 `confident`、`tentative` 和 `clarify`。高置信度才给细分类；中置信度建议确认；低置信度进入开放式追问，避免机器人自信地判断错误。

## 三、数据与评测

### Q8：用了哪些数据？

**回答：**

> 主要使用两套公开中文数据。第一套是 MIT 许可的 Chinese Multi-Emotion Dialogue，映射后 3271 条；第二套是 CC-BY-4.0 的 BRIGHTER 中文数据，官方 train/dev/test 分开使用。

### Q9：训练、验证、测试各多少？

**回答：**

> 最终模型训练集由 BRIGHTER train 2445 条和另一套数据 train 2297 条组成，共 4742 条。BRIGHTER dev 190 条用于早停和校准。BRIGHTER test 中 1000 条用于开发和错误分析，剩余 1449 条一直封存，最终才评估。

### Q10：1000 条和 1449 条为什么结果不同？

**回答：**

> 它们是不同测试样本。1000 条用于和 Qwen 做同一集合公平对照；1449 条是另外未参与开发分析的密封集合。不能把两组数字混成一次统计。

### Q11：有没有数据泄漏？

**回答：**

> 没有把 BRIGHTER test 放进训练。训练只用官方 train 和另一套数据 train；早停只用 dev；1449 条最终测试在评估前未使用。但公开数据没有说话人字段，因此只能叫对话/文本防泄漏，不能叫说话人隔离。

### Q12：同源 test 91.8% 算不算跨数据集泛化？

**回答：**

> 不算。它说明模型在同一来源独立 test 上表现好，尤其是焦虑 F1 88.9%、Recall 92.6%。跨数据集结果应看 BRIGHTER 1000 条的 76.5% 和密封集的 80.2%。

### Q13：为什么有 80% Accuracy，Macro-F1 只有 75%？

**回答：**

> 数据类别不平衡，愤怒类样本较多。Accuracy 受大类影响较大，Macro-F1 对每个类别平均，更能反映少数类表现。因此我同时报告 Accuracy、Macro-F1、UAR、逐类召回和混淆矩阵。

### Q14：标签怎么映射？

**回答：**

> BRIGHTER 中 joy 映射高兴、sadness 映射悲伤、fear 映射焦虑，anger 和 disgust 合并为愤怒/烦躁，所有强度为零映射中性，surprise 不作为当前六类目标。标签并列样本被排除。

### Q15：为什么没有真正评测 `calm`？

**回答：**

> 两套公开训练/评测数据没有稳定的 calm 标签。微调模型输出五类，`calm` 目前由规则的明确平静线索补充。因此完整六类里，calm 还没有经过同等强度的监督测试。

## 四、模型训练细节

### Q16：最终模型是什么？

**回答：**

> 基座是 `hfl/chinese-roberta-wwm-ext`，做多任务监督微调。三个 epoch，batch size 8，最大长度 192，冻结前六层，学习率 `2e-5`，运行在 Apple M5 MPS 上。

### Q17：多任务损失怎么设计？

**回答：**

> 主任务为五类交叉熵，辅助任务包括多标签情绪 BCE、负面/非负面 BCE 和情绪强度 SmoothL1。主分类使用类别权重和 `0.05` 标签平滑，降低类别不平衡和标注噪声影响。

### Q18：为什么要加入另一套数据？

**回答：**

> BRIGHTER train 只有 34 条焦虑，最初跨数据集焦虑 Recall 只有 19.4%。加入 2297 条训练样本并设置 0.5 权重后，焦虑 training 数据达到 428 条；另一套独立 test 上焦虑 F1 提升到 88.9%。

### Q19：推理速度多少？

**回答：**

> 微调 RoBERTa 热推理约 0.14 秒，应用端到端文本请求约 216～314 ms。Qwen 回退模型约 1.3～1.8 秒，因此它不作为默认主路径。

### Q20：为什么多标签头没有直接使用？

**回答：**

> 固定 70/30 多标签融合让 Macro-F1 从 66.0% 降到 63.8%；在 dev 上自动搜索权重后又出现 test 退化。因此多标签概率只作为辅助证据保留，主决策继续使用主分类头。

### Q21：层级分类为什么没上线？

**回答：**

> 我训练了“中性门控 + 四类细分类”的冻结特征分类器。它在 dev 上略好，但密封集 Accuracy 79.8%，低于扁平模型 80.2%；焦虑 test 也略低。没有明显收益，所以没有替换线上模型。

## 五、系统与安全

### Q22：低置信度怎么处理？

**回答：**

> 不强行生成细粒度标签。系统输出 `clarify`，建议机器人用开放式问题确认，例如“听起来你不太好受，愿意多说说吗”。

### Q23：风险识别和情绪识别是什么关系？

**回答：**

> 两者独立。普通情绪分类置信度低，不代表风险可以忽略。风险分支使用单独高召回规则，输出 `none/watch/urgent`。当前还没有风险标注集，所以只能作为演示级安全提醒，不能替代人工流程。

### Q24：隐私怎么保证？

**回答：**

> 原始音频在浏览器内生成 16 kHz WAV，只通过 `127.0.0.1` 发送给本机模型服务；推理后删除临时文件，不调用外部模型 API。会话状态只在内存中保存，默认四小时后过期。

### Q25：方言现在能不能用？

**回答：**

> 接口可以接收方言代码，但当前没有方言 ASR、方言情绪模型或方言校准。响应会明确返回 `requested`、`used: mandarin`、`supported: false`、`mode: fallback`，不会把普通话结果冒充方言结果。

## 六、最可能被追问的问题

### “这个 80.2% 可信吗？”

**建议回答：**

> 这是官方 test 补充集上的结果，样本在调参和开发分析前未使用，因此比手写小样本可信。但数据没有说话人字段，所以它是文本级密封测试，不是严格的说话人隔离测试。我不会把它说成最终产品精度。

### “为什么不继续调到 90%？”

> 当前主要错误是中性、轻怒和悲伤边界，以及缺少多轮上下文。继续在同一公开集上追求涨点容易过拟合，下一阶段应采集目标陪伴对话，而不是重复调参。

### “你的创新点是什么？”

> 基础模型来自开源社区。我的工作是把多任务微调、规则保护、语音情绪融合、低置信度澄清和完整外部评测组合成可运行模块。当前更偏工程与评测贡献，尚没有提出全新的算法结构。

### “两周做了这么多，真实吗？”

> 我只负责情感识别，没有展开人格和方言生成；实现使用现成开源模型和本地工具完成。产物包含 29 项自动测试、训练脚本、数据指纹、密封测试和失败实验，均可复现。核心科学研究仍未完成。

## 七、一句话兜底

如果被问：

> **“你现在这个模块到底能不能用？”**

可以回答：

> 能作为陪伴机器人原型使用，适合给出粗粒度情绪提示和低风险共情回应；高置信度时可以提供细分类，低置信度时必须追问。它不能用于心理诊断、人格定性、危机救援或未经训练的方言场景。
