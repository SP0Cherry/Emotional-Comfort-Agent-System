## 1. 文档目的

本文档定义情感识别模块的职责边界、输入输出、功能要求、接口契约、质量指标、数据与隐私要求，以及团队联调方式。

本模块不只输出“开心、难过”等离散标签，而是估计用户在当前对话中的连续情绪状态，为回应策略、人格建模和方言语音合成提供稳定的控制信号。

**当前实施范围**：v0.4 普通话 MVP。`mandarin` 和 `zh-CN` 是原生支持值。其他安全格式的方言代码允许进入接口，但必须返回 `mode: fallback`、`supported: false` 和明确的未校准警告。方言 ASR、方言模型和方言数据验证推迟到后续版本。

## 2. 模块定位

### 2.1 核心目标

1. 识别用户当前的主要情绪、情绪强度和置信度。
2. 估计效价（Valence）和唤醒度（Arousal），描述“好受/难受”和“平静/激动”。
3. 跟踪多轮对话中的情绪变化，识别持续、升级、缓和和波动等情况。
4. 在方言 ASR 质量较差、背景噪声或缺少摄像头时仍能降级工作。
5. 输出独立、高召回的风险信号，提示对话系统进入安全干预流程。
6. 向人格建模和方言输出模块提供稳定、可解释、带时间戳的接口。

### 2.2 不负责的内容

1. 不进行抑郁症、焦虑症等医学诊断。
2. 不根据单轮对话判断用户稳定人格，人格建模由对应模块负责。
3. 不生成陪伴回复、长期记忆或人设内容。
4. 不直接合成方言语音，只向 TTS 提供情绪和韵律控制状态。
5. 不把表情单独作为情绪判断结论。
6. 不保证正确识别反讽、掩饰情绪和复杂心理状态，但必须通过置信度表达不确定性。

## 3. 术语与状态定义

- **轮次（Turn）**：一次用户发言从开始到 VAD 检测到端点为止。
- **情绪状态（Emotional State）**：当前窗口内推断出的暂时性情绪，不等同于人格或心理诊断。
- **效价（Valence）**：情绪的正负性，范围为 `[-1, 1]`，负值表示难受、负向。
- **唤醒度（Arousal）**：情绪激活程度，范围为 `[0, 1]`，高值表示激动、紧张或高能量。
- **情绪强度（Intensity）**：当前情绪相对用户个人基线的明显程度，范围为 `[0, 1]`。
- **置信度（Confidence）**：本模块对本次结果的可靠程度，范围为 `[0, 1]`。
- **风险信号（Risk Signal）**：与普通情绪分类分开的自伤、他伤或严重危机提示。

## 4. 系统边界与数据流

```mermaid
flowchart LR
    A["音频 / 文本 / 可选视频"] --> B["预处理与质量检测"]
    B --> C["文本、语音、视觉分支"]
    C --> D["置信度校准与多模态融合"]
    D --> E["多轮情绪状态跟踪"]
    E --> F["情绪状态与风险信号输出"]
    F --> G["人格建模 / 回应策略 / 方言 TTS"]
```

## 5. 情绪标签体系

### 5.1 一级情绪标签

第一版使用以下六个互斥的一级标签：

| API 值 | 中文名称 | 典型说明 |
| --- | --- | --- |
| `joy` | 高兴 | 愉悦、兴奋、积极 |
| `calm` | 平静 | 放松、稳定、低唤醒 |
| `sadness` | 悲伤 | 失落、难过、低落 |
| `anxiety` | 焦虑 | 担心、紧张、不安 |
| `anger_irritation` | 生气/烦躁 | 愤怒、厌烦、明显不满 |
| `neutral` | 中性 | 没有明显情绪倾向 |

模型需同时输出所有类别的概率分布，不能只返回一个标签。

### 5.2 陪伴场景的二级线索

以下内容不属于一级情绪，作为可选的辅助信号输出：

- 孤独、委屈、疲惫、无助、释然等状态标签；
- 可能需要安慰、陪伴、倾听、实际帮助、转移注意、共同庆祝或进一步澄清；
- 这些线索必须附带置信度，低置信度时不得直接驱动强烈回复。

### 5.3 风险等级

| API 值 | 含义 | 系统行为 |
| --- | --- | --- |
| `none` | 未发现明确风险 | 正常回应 |
| `watch` | 存在模糊或间接风险线索 | 进入谨慎回应与继续关注 |
| `urgent` | 出现明确自伤、他伤或紧急求助线索 | 进入高优先级安全流程，必要时提示人工介入或紧急资源 |

风险检测应独立于普通情绪分类，避免“情绪不强烈”导致风险被漏掉。风险结果只能用于提示和升级处理，不能作为医疗诊断。

## 6. 功能需求

### FR-01 输入与预处理

模块应接收一轮用户音频、ASR 结果和可选的视觉输入，并完成：

- 输入格式与时长校验；
- VAD、降噪、音量归一化和说话人切分；
- 音频质量估计，包括静音、削波、噪声和有效语音时长；
- ASR 置信度和方言标识读取；
- 视频可用性、人脸覆盖率和画面质量检查。

### FR-02 文本情绪分支

模块应根据 ASR 文本识别语义情绪、强度线索、求助意图和风险线索，并保留 ASR 置信度供后续融合使用。

当 ASR 文本为空或明显错误时，该分支应返回不可用状态，不得用默认文本强行分类。

### FR-03 语音情绪分支

模块应直接使用语音声学信息进行情绪判断，包括但不限于：

- 音高及其变化；
- 能量和音量；
- 语速、停顿和节奏；
- 频谱、音质和声音稳定性；
- 方言特有的韵律差异。

该分支不得完全依赖 ASR 转写结果。

### FR-04 视觉情绪分支

当摄像头启用且画面质量合格时，可分析面部表情、头部姿态和可见动作。视觉结果只作为融合证据，不得单独决定最终情绪。

摄像头不可用或用户关闭摄像头时，模块必须正常返回文本与语音结果。

### FR-05 质量评估与置信度校准

每个模态应输出：

- 是否可用；
- 输入质量分；
- 分类置信度；
- 不可用或降级原因。

分类器概率必须经过温度缩放、Platt scaling 或同类校准方法处理。未经校准的 softmax 概率不能直接作为对外置信度。

### FR-06 多模态融合

融合层应满足：

- 根据模态质量和置信度动态调整权重；
- 支持文本、语音、视觉任意模态缺失；
- 对模态冲突给出较低置信度，不能简单平均后强行下结论；
- 记录参与融合的模态、权重和证据摘要，便于调试与答辩展示。

第一版建议采用可解释的置信度加权或轻量分类器；只有在有多模态对齐训练数据时才升级到学习式融合模型。

### FR-07 多轮情绪状态跟踪

模块应维护会话级窗口，输出：

- 当前主情绪和概率分布；
- 效价、唤醒度和强度；
- 情绪趋势：`improving`、`stable`、`worsening`、`fluctuating`、`insufficient_data`；
- 低效价持续时长；
- 连续多轮结果的稳定性；
- 最近若干轮的关键变化点。

趋势计算必须指定时间窗口，建议以最近 3～5 轮或最近 60 秒为初始窗口，具体值在数据试验后冻结。

### FR-08 方言与个人基线适配

模块应记录当前使用的方言和校准状态。对已支持的方言，可使用方言校准器修正情绪分布、效价和唤醒度。

可使用用户在当前会话中的平稳状态作为个人基线，用于判断情绪变化幅度，但不得在缺乏数据时虚构个人画像。

### FR-09 风险信号检测

模块应检测直接或间接的自伤、他伤、严重绝望、虐待和紧急求助线索，并输出风险等级、原因代码、证据模态和置信度。

风险逻辑应优先保证召回率；误报通过更谨慎的追问和分级处理来管理，不能为了降低误报直接忽略风险线索。

### FR-10 状态输出与审计

每轮应生成结构化情绪状态，并记录：

- 模型和规则版本；
- 输入质量；
- 各模态结果；
- 融合结果；
- 风险判断；
- 推理耗时；
- 是否使用降级模式。

默认不记录原始音视频，只记录实现质量评估、复现实验和故障排查所需的最小信息。

### FR-11 降级运行

| 异常场景 | 必须行为 |
| --- | --- |
| ASR 不可用 | 继续使用语音分支，返回 `partial` |
| 摄像头不可用 | 使用文本与语音，不报错 |
| 音频过短或无语音 | 返回 `insufficient_data` 和原因 |
| 单一模型超时 | 使用其余可用模态返回 `partial` |
| 全部模态不可用 | 返回 `error`，不得编造情绪结果 |
| 方言不支持 | 使用通用模型，并标记 `dialect_calibrated=false` |

## 7. 对外接口规约

### 7.1 推荐接口形式

- 实时交互：WebSocket 或内部流式 RPC；
- 单轮调试：HTTP `POST /api/v1/emotion/turns`；
- 会话查询：HTTP `GET /api/v1/emotion/sessions/{session_id}`；
- 会话清理：HTTP `DELETE /api/v1/emotion/sessions/{session_id}`。

如项目统一使用其他通信方式，可保持本文档定义的字段语义不变。

### 7.2 逻辑输入

```json
{
  "request_id": "req-20261101-0001",
  "session_id": "sess-demo-001",
  "turn_id": 7,
  "timestamp": "2026-11-01T20:30:00+08:00",
  "audio": {
    "uri": "internal://turn-7.wav",
    "sample_rate_hz": 16000,
    "channels": 1,
    "duration_ms": 4200
  },
  "asr": {
    "text": "最近真的很烦，什么都不想干",
    "confidence": 0.78,
    "dialect": "mandarin"
  },
  "vision": null,
  "context": {
    "recent_emotions": ["sadness", "anxiety"],
    "recent_valence": [-0.42, -0.51]
  }
}
```

说明：

- `audio.uri` 是内部资源引用示例，生产接口不应把大段音视频直接塞入 JSON。
- `context` 可由服务端会话状态自动维护；作为输入传入时用于无状态调用。
- 用户身份必须使用匿名化 ID，不得使用手机号、姓名等直接身份信息。

浏览器演示版会在本地提取并发送以下可选声学摘要，不发送原始音频：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `duration_ms` | integer | `0～120000` |
| `speech_ratio` | number | `[0, 1]` |
| `mean_db` | number | `[-90, 0]` |
| `variation_db` | number | `[0, 60]` |
| `mean_pitch_hz` | number | `[0, 600]` |
| `pitch_variation_hz` | number | `[0, 300]` |
| `pause_count` | integer | `0～100` |
| `clipping_ratio` | number | `[0, 1]` |

### 7.4 状态枚举

- `ok`：主要模态可用，结果完整；
- `partial`：至少一个模态不可用，但仍有有效结果；
- `insufficient_data`：输入过短、静音或有效信息不足；
- `error`：无法产生结果。

## 8. 与其他模块的契约

### 8.1 向人格建模模块

人格模块可以消费：

- 当前情绪状态；
- 可靠的情绪趋势；
- 多轮情绪基线、波动性和稳定程度；
- 带置信度的陪伴需求线索。

人格模块不得把单轮情绪直接转换成“敏感、悲观、易怒”等稳定人格标签。若需要长期情绪画像，应由人格模型在更长周期上聚合，并保留数据来源与置信度。

### 8.2 向回应策略模块

回应策略模块至少应读取：

- `dominant_emotion`；
- `valence`、`arousal`、`intensity`；
- `temporal.trend`；
- `risk.level`；
- `companion_needs`；
- 整体置信度。

当整体置信度低于约定阈值时，回应策略应倾向于澄清或温和追问，不能做出强烈判断。

### 8.3 向方言输出模块

方言 TTS 可使用效价、唤醒度、强度和趋势控制：

- 语速；
- 音高范围；
- 能量；
- 停顿；
- 韵律柔和度。

情绪标签不能直接映射为固定音高或语速。方言 TTS 模块负责最终声学参数映射和听感校准。

联动时必须处理语音回声和机器人自身声音，防止 TTS 输出被情感识别模块误当成用户输入。

## 9. 非功能需求

### NFR-01 延迟

在项目参考硬件上：

- 一轮结束后 `800 ms` 内应返回最终结果，目标值为 `p95`；
- 流式中间状态可每 `300～500 ms` 更新一次，最终状态以轮末结果为准；
- 模型超时必须触发降级，不得阻塞对话主流程。

上述数值为首版建议指标，参考硬件确定后需补充具体 CPU/GPU 条件。

### NFR-02 鲁棒性

- 支持 16 kHz 及以上单声道语音；
- 允许背景噪声、短停顿、短暂重叠和方言口音；
- 任一可选模态缺失不得导致服务崩溃；
- 同一输入重复推理的结果差异应在可接受范围内；
- 对低置信度结果明确标记，而不是输出看似确定的结论。

### NFR-03 隐私与安全

- 使用摄像头和录音前应获得用户明确同意；
- 第一版声学分支只在浏览器本地计算特征摘要，不上传或保存原始音频；
- 默认本地处理原始音视频，不上传云端，不长期保存；
- 数据库中仅保存匿名会话 ID、结构化状态和必要日志；
- 用户应能关闭摄像头、停止识别并请求删除会话数据；
- 风险提示应提供真实可用的求助路径，不能承诺机器人能够提供医疗或紧急救援；
- 日志中不得记录密码、直接身份信息或未经脱敏的完整对话。

### NFR-04 可维护性

- 模型、规则、方言校准器和阈值均需版本化；
- 每条结果应可追溯至所用版本；
- 标签、字段和枚举变更必须升级 `schema_version`；
- 新增方言不得破坏通用分支。

## 10. 数据与标注规范

### 10.1 最小数据需求

首版优先覆盖实际演示的 1～2 种方言。每种方言建议至少包含：

- 8～15 名不同年龄和性别的说话人；
- 每人 30～50 条自然对话或半结构化对话；
- 覆盖六类情绪和不同强度；
- 包含安静、轻度噪声和设备差异场景；
- 至少一部分多轮对话，避免只有孤立的表演式语句。

### 10.2 划分要求

- 训练、验证和测试集必须按说话人完全隔离；
- 若存在多种方言，测试集不得只来自训练方言；
- 报告结果时需区分干净数据、噪声数据和 ASR 低置信度数据；
- 不得把同一原始音频的切片同时放入训练集和测试集。

### 10.3 标注要求

- 情绪标签、效价、唤醒度和强度必须分别定义；
- 至少双人标注关键测试集，记录标注者一致性；
- 允许“无法判断”，不得强制标注模型不可见的信息；
- 用户自评可作为参考，但不能替代客观声学与行为证据；
- 风险语句需单独审核和脱敏处理。

## 11. 评价指标与建议验收线

以下为首版建议目标，需在导师确认数据规模和基线结果后冻结：

| 指标 | 建议目标 | 说明 |
| --- | --- | --- |
| 六分类 Macro-F1 | ≥ 0.60 | 防止只靠多数类取得高准确率 |
| Unweighted Average Recall | ≥ 0.55 | 关注少数情绪类别 |
| 效价 MAE | ≤ 0.20 | 连续维度误差 |
| 唤醒度 MAE | ≤ 0.18 | 连续维度误差 |
| 置信度 ECE | ≤ 0.10 | 置信度校准 |
| 风险召回率 | ≥ 0.90 | 安全优先，允许一定误报 |
| 最终结果延迟 p95 | ≤ 800 ms | 在固定参考硬件上 |
| 降级模式成功率 | ≥ 99% | 缺少模态时不崩溃 |

若数据规模不足以支持上述目标，应在实验报告中明确说明限制，不能自行降低测试标准或只在训练分布内展示结果。

### 11.1 必需对照实验

1. 文本单独；
2. 语音单独；
3. 文本与语音简单融合；
4. 质量加权的多模态融合；
5. 融入多轮上下文；
6. 融入方言或个人基线校准；
7. 缺少 ASR、噪声和缺少视觉输入时的鲁棒性。

### 11.2 人类感知评价

除离线指标外，建议让测试用户判断：

- 机器人是否理解了当前情绪；
- 识别结果是否与用户自评一致；
- 回应强度是否合适；
- 情绪变化是否被合理跟踪；
- 机器人是否显得过度诊断或冒犯。

## 12. 测试要求

### 12.1 功能测试

- 正常有声输入；
- 文本可用但音频质量差；
- 音频可用但 ASR 置信度低；
- 摄像头缺失或关闭；
- 无语音、静音和超短输入；
- 方言切换；
- 多轮情绪改善、恶化和波动；
- 风险线索和正常负面情绪混淆。

### 12.2 鲁棒性测试

- 背景噪声、回声和多人说话；
- 麦克风音量过低或削波；
- 说话人距离变化；
- 强口音、方言词、中英混说；
- 反讽、含糊表达和自嘲；
- 长时间低落但表达平静。

### 12.3 安全与隐私测试

- 明确自伤表达必须触发 `urgent`；
- 间接风险表达不得被普通情绪分类吞掉；
- 关怀性日常表达不能被高比例误判为危机；
- 未授权时不得开启摄像头或录音；
- 会话删除后无法通过接口恢复原始数据；
- 日志中不存在直接身份信息。

## 15. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 方言情绪数据不足 | 模型泛化差 | 先用普通话或公开数据预训练，再采集目标方言校准集 |
| 方言 ASR 准确率低 | 文本分支失效 | 保留独立语音情绪分支，质量加权融合 |
| 表演式数据与真实对话不一致 | 演示效果虚高 | 加入自然多轮对话和真实场景验证 |
| 情绪标签主观性强 | 标注一致性低 | 多维标签、多人标注、记录一致性 |
| 摄像头不稳定 | 视觉分支噪声大 | 视觉设为可选，按质量动态降权 |
| 类别不平衡 | 准确率虚高 | 使用 Macro-F1、UAR 和混淆矩阵 |
| 风险检测误报或漏报 | 安全与体验受损 | 独立高召回分支、分级处理、人工兜底 |
| 在线保存音视频 | 隐私风险 | 默认端侧处理，只保存最小结构化信息 |
