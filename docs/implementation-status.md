## 实际执行的验证

后端以 Python 3.12.15 运行，使用真实 PostgreSQL/pgvector，没有用 SQLite 替代集成环境。

- 最终完整回归：**49 项通过，8.35 秒**。使用 Docker `pgvector/pgvector:pg17`，数据库 PostgreSQL 17.11、pgvector 0.8.7。
- 早期原生 Windows PostgreSQL 17.5 环境也完成主流程与租约竞争验证；该临时实例已停止。
- Ruff 静态检查、Python 编译检查与 PowerShell 脚本语法检查通过。
- Docker 镜像实际构建成功；Alembic 从空库迁移成功。API、Worker 使用相同 `elder-companion-backend:0.1.0-dev` 镜像运行。
- 一键脚本首次生成随机凭据，启动成功；再次启动保留数据且成功。
- `scripts/smoke.py` 对真实 HTTP API 与独立 Worker 的验证通过：登录 → 人物 → 回复持久化 → 候选抽取 → 确认及向量化 → 私有导出 → 异步全量清除 → 空历史 → 退出登录。
- Flutter 依赖已解析并生成 `mobile/pubspec.lock`（95个依赖包；Flutter ≥ 3.47、Dart ≥ 3.13）。验证使用 Dart 3.13.5 和官方 stable 源码，对应 Flutter engine `deb287481e3ce9468f3434937ced4240a70539ca`。
- `flutter analyze --no-pub`：**No issues found，11.4秒**；`flutter test --no-pub --reporter expanded`：**9项全部通过，约3秒**。
- 客户端测试覆盖每个 UTF-8 字节边界的 SSE 解析、重放去重、令牌单次刷新、幂等重发、原 run 重连、历史合并，以及开发验证码登录后进入已登录人物页面。
- 已实际尝试 `flutter build apk --debug --no-pub`，构建工具报告 **No Android SDK found**；因此没有产出 APK，也未验证 Gradle/Kotlin 原生构建和真机运行。

回归用例包含10次并发幂等提交、单会话活动任务、跨账户 UUID/SSE/记忆/头像隔离、刷新令牌旧值重放、UTF-8 分块、上游 usage 独立块与推理内容隔离、模型429/中断、取消时传输异常、租约在事务等待期间过期、旧向量迟到、用户移除来源后重新抽取、输出替换、试聊隔离和清除上下文。

## 尚未验证或尚未实现

- 未提供真实百炼工作空间和 API Key，因此没有执行真实云模型请求、模型成本或延迟评测。模型 HTTP 协议使用受控 Mock Transport 验证。默认 `PROVIDER_MODE=mock`，模拟响应不能代表真实模型效果。
- 真实短信、云 OSS、语音输入/朗读、联系人验证与现实联络尚未实现；生产启动主动拒绝开发短信配置。风险分支只记录内部事件和展示受控提示，不宣称已通知任何人。
- 当前记忆相关性使用保守的文字相关过滤，语义阈值和效果需要中文案例评测；规则与模型检查也不能保证消除全部虚构。
- 已实现用户每日聊天额度、验证码和上传限流；账号总金额预算、完整阶段成本台账、跨多个 Worker 的全局并发限制、定时事件保留清理、完善监控和备份恢复仍待上线阶段实现。
- 4并发100轮性能目标、200个固定人工评分案例、老人目标机型与真实用户可用性验证尚未执行。
- 当前未配置 Android SDK，APK 构建、设备安装与发布签名尚未完成。Android 工程包含与所用 Flutter 模板一致的 Gradle wrapper、AGP/Kotlin 配置；仍需在完整 Android 工具链上实际构建。
